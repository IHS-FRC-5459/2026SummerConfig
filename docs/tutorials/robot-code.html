Read config from robot code

Paths mirror the JSON tree. Use the right getter, and know when to hold a reference.

Paths

Slash-separated names from the root of robot-config.json. Example: Arm/PIDController for a PID node, Arm/PIDController/p for its p field.

Typed getters

ConfigDocument doc = configManager.getDocument();

double kP = doc.getDouble("Arm/PIDController/p");
PIDController pid = doc.getPIDController("Arm/PIDController");
Pose2d start = doc.getPose2d("Robot/StartPose");

Missing or wrong-type paths log a [Config] warning and return a safe default (0, false, empty string, Pose2d.kZero, a new zero PID — not your config instance).

Hold PID once; re-read poses

public class ArmSubsystem extends SubsystemBase {
  private final PIDController armPid;

  public ArmSubsystem(ConfigManager config) {
    // Live composite — same object, gains update in debug
    armPid = config.getDocument().getPIDController("Arm/PIDController");
  }

  @Override
  public void periodic() {
    double out = armPid.calculate(setpoint, getMeasurement());
    // ...
  }
}
public void resetOdometry(ConfigDocument config) {
  // Immutable composite — call getter when you need the current value
  Pose2d start = config.getPose2d("Robot/StartPose");
  odometry.reset(start);
}
Same idea for ProfiledPIDController (hold) vs scalars, translations, feedforwards, and other value types (re-read).
