Debug vs match mode

Same dashboard, different rules. Match mode protects competition values; debug mode lets you tune and create.

Debug Match
Condition Not on FMS and /Config/DebugMode true FMS attached or DebugMode false
Getters Live NT-backed document Defaults loaded from robot-config.json
NT edits Applied; parents sync (e.g. PID gains) Ignored
JSON Autosave cache; promote with Save / layout watch No writes
Create / Delete Enabled Not applied

Typical pit workflow

  1. Not connected to FMS. Turn DebugMode on.
  2. Tune scalars; confirm robot behavior (getters see live values).
  3. Press Save to write robot-config.json.
  4. Commit / deploy that file so the competition robot has the new defaults.
  5. At the event, leave DebugMode off (or accept that FMS forces match). Dashboard still shows values; edits do not change what code uses.
If you only autosave to cache and never Save + deploy, the next boot (and match mode) still uses the old committed robot-config.json.
