Using guide

Quick reference for files, modes, NetworkTables topics, and reading config from robot code.

Files

File Purpose
robot-config.json Committed defaults in deploy. Loaded at startup. Written when you promote (Save or Elastic Save As on the watched layout file).
config-cache.json Debug scratch. Live NT edits autosave here. Not what you ship for match unless you promote.
elastic-layout.json Default watched file next to the config. Content changes (e.g. Elastic Save As) can promote the live document into robot-config.json.

Modes

Debug Match
When !FMS and /Config/DebugMode true FMS attached, or DebugMode false
Getters Live NT-backed document JSON defaults from robot-config.json
NT writes Applied + cache autosave Ignored (publish for display only)
JSON writes Cache always; promote to robot-config on Save / layout watch None

See also the debug and match tutorial.

NetworkTables topics

Topic Role
/Config/DebugMode Toggle switch — enable debug when not on FMS
/Config/Save Momentary button — promote live document to robot-config.json
/Config/Create/Folder Parent folder chooser ((root) or nested path)
/Config/Create/Type Type chooser (Folder, scalars, composites)
/Config/Create/Name New entry name (text with submit)
/Config/Create/Go Pulse true to create; robot clears it
/Config/Delete/Path Path chooser ((none) = no-op)
/Config/Delete/Go Pulse true to delete; robot clears it
/Config/... Your config tree — folders as subtables, scalars as entries

Robot API

Construct once in robotInit, call periodic() every loop:

configManager = new ConfigManager(
    new File(Filesystem.getDeployDirectory(), "robot-config.json"),
    new File(Filesystem.getDeployDirectory(), "config-cache.json"));

// robotPeriodic
configManager.periodic();

PIDController armPid =
    configManager.getDocument().getPIDController("Arm/PIDController");

Paths use slash-separated names that mirror the JSON folder structure (e.g. Arm/PIDController/p).

Live vs immutable values

  • PID / ProfiledPID — fetch once and hold the reference. Gains update in place when you tune in debug.
  • Poses, translations, scalars, feedforwards — call the getter when you need the current value; composites rebuild when children change.

Promoting cache → robot-config

Publish Values ≠ Save. Elastic widgets with a Publish Values button (e.g. PIDController) only send NT updates when you click that button — Config then can autosave config-cache.json. They never write robot-config.json. Promote with our /Config/Save control (or the layout-file watcher).
  1. Press Save on the dashboard (/Config/Save), or
  2. Change the content of the watched file (default elastic-layout.json, e.g. Elastic Save As).

Then commit/deploy robot-config.json so match mode and the next boot use the new defaults.

Simulation notes

  • For Elastic connecting to sim, use host 127.0.27.1 (see project README).
  • Cache writes go to Filesystem.getDeployDirectory() — often under build/..., not necessarily src/main/deploy. Check the log line [Config] Saved config cache: for the absolute path.
Elastic does not auto-reload layout JSON after Create/Delete UI changes — re-import or reopen the layout file.
